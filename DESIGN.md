# Design System: Mochammad Ariel Sulton Portfolio

## Overview

**Creative North Star: "The iOS Collection"**

The portfolio uses the grouped surfaces of an iOS collection: cool purple-tinted ground, frosted inset surfaces, a near-black Dynamic Island, and an expressive opening made from flowing purple wallpaper and reflective glass. The local Masalabs project informed this material vocabulary; the implementation here is the authority for future portfolio surfaces.

Schibsted Grotesk carries both the large personal introduction and compact interface text. Photographs, screenshots, and logos provide subject-specific detail; open experience chronology, grouped skill rows, and clear disclosure keep the existing work readable. Light and dark themes preserve the same hierarchy, while the contact sheet remains dark in both.

**Key Characteristics:**
- Cool grouped grounds with translucent, bright-edged content sheets.
- Large tight headings and compact sentence-case controls.
- Purple details, a responsive dark Dynamic Island, and a dark contact sheet.
- Visible glass containers, a flowing hero field, and an open alternating experience timeline.
- Responsive disclosure and quiet state changes with reduced-motion support.

## Colors

A cool neutral palette carries the reading experience, while purple marks small points of emphasis. Theme-aware purple and blue wallpaper colors animate the opening and tint the grouped ground.

### Primary
- **Ink / Paper:** `primary` and `primary-foreground` form high-contrast actions. In dark mode they invert to light ink on the dark page. The fixed navigation and contact sheet retain their dark material.
- **Purple Detail:** `purple` marks identity dots; `purple-ink` supplies readable annotations, list markers, skill levels, and timeline progress. The dark theme uses its lighter counterpart. The wallpaper tokens form a separate atmospheric palette, without replacing reading ink.

### Neutral
- **Grouped Gray:** `background` is the page field and default subtle fill; `secondary` supplies segmented tracks and hover fills.
- **Frosted Surfaces:** `surface-glass` and `surface-line` supply the visible translucent reading containers and their bright edge; dark equivalents preserve tonal separation. `card` remains the semantic backing color.
- **Quiet Ink:** `muted-foreground` carries descriptions and metadata. Border tokens provide fine internal separators.
- **Hero Glass:** `glass` and `glass-line` create translucent panels against the wallpaper, with theme-specific equivalents.
- **Focus Purple:** `ring` supplies the keyboard outline, changing to the lighter purple in dark mode.

**The Grouped Ground Rule.** Group related content on frosted surfaces against the tinted background; use separators inside a group rather than elevating every row. Experience follows an open chronology on the ground.

Theme values in frontmatter describe the paired implementation tokens. Runtime components use the existing semantic CSS custom properties, whose dark overrides are declared in `src/styles.css`.

## Typography

**Display Font:** Schibsted Grotesk, with Apple/system sans-serif fallbacks.
**Body Font:** The same self-hosted variable family, served as a Latin WOFF2 with font-display swap.

**Character:** Broad, direct sans-serif lettering becomes personal through generous scale and tight heading tracking; smaller interface text stays compact and readable.

### Hierarchy
- **Display:** The large name uses the display role; the mobile clamp becomes `clamp(2.8rem, 11vw, 4rem)`.
- **Headline:** Section headings use the headline role, becoming a fixed (35px) below the mobile breakpoint.
- **Title:** Project titles use the project-title role; experience titles use (26px) and skills titles use (27px), with mobile counterparts (22px) and (24px). Mobile project titles become (23px).
- **Body:** The global body role is the base. Descriptions generally use (14–18px); the about narrative uses (19px), a generous (1.75) leading, and a (75ch) maximum measure before mobile adjustment.
- **Action:** Buttons use the action role. Compact labels and metadata generally use (11–15px), in natural sentence case.

The frontmatter records the observed type steps by purpose, including small metadata, mobile variants, statistics, and the contact display. These are functional sizes rather than a fixed geometric ratio.

**The One Family Rule.** Use Schibsted Grotesk for display and interface roles; express hierarchy through scale, weight, and spacing.

## Layout

The shared content container is centered with a maximum width (1160px) and desktop side allowance (80px total). Sections use substantial top spacing (76px) with shorter trailing spacing (30px). Below (700px), the container leaves (16px) per side and section top spacing becomes (54px).

Projects use two columns with a (24px) gap; achievements use three columns with a (20px) gap. Achievements reduce to two columns below (999px); both collections become single columns below (700px), with an (18px) gap. Experience alternates across two open columns around a central rail with logo nodes, a (112px) column gap, and (58px) row spacing. Below (700px), a left rail and (76px) content inset preserve the chronology with (40px) row spacing. Skills combine a category sidebar with a content panel; on mobile the categories become a horizontal scrolling row. Contact uses two columns on desktop and stacks on mobile.

The fixed island uses intrinsic content width with a viewport allowance (32px), independent of the reading container. Below (999px), its closed width (274px) expands to a maximum (390px) while the mobile menu opens. Anchored navigation accounts for the header with scroll padding (104px).

## Elevation & Depth

Depth comes from translucent tonal layers, bright borders, inset reflections, and restrained diffuse shadows. About, skills, projects, achievements, and footer share frosted glass (28px blur, 160% saturation) over a lightly purple-tinted ground. Hero glass is more transparent, with stronger blur (32px), saturation (185%), and a diagonal reflection. The contact sheet stays dark and solid for the form.

### Shadow Vocabulary
- **Navigation island:** `0 12px 32px -18px rgb(12 5 25 / 65%), inset 0 1px 0 rgb(255 255 255 / 10%)` anchors the capsule.
- **Reading glass:** `inset 0 1px 0 rgb(255 255 255 / 35%)` catches its upper edge.
- **Portrait:** `0 16px 32px -20px rgb(27 18 50 / 40%)` separates the circular profile photograph from the wallpaper. The portrait is upright, 180px on desktop and 144px on mobile, with a head-and-shoulders crop, a pale purple ground, and a fine outline. It must read as a personal photograph rather than a tilted app icon.
- **Selected thumb:** `0 3px 6px -4px rgb(0 0 0 / 35%)` marks the selected project filter.
- **Timeline node:** `0 6px 16px -12px rgb(31 14 59 / 40%)` lifts the logo only.

**The Readable Glass Rule.** Preserve visible translucency and bright edges while keeping reading ink contrast clear. Experience text stays on the open ground; reserve its glass for logo nodes.

## Shapes

The hero has a rectangular edge with square corners at all viewport sizes, as explicitly requested by the user. Do not add a curved mask or rounded bottom edge.

Large grouped sheets use the sheet radius, tightening to the mobile-sheet radius on small screens. Project and award cards have their own adjacent rounded forms; image corners sit inside the outer card. Pill actions, circular icon controls, gently rounded fields and category selections, and small rectangular technology tags each communicate a different function. The island radius morphs from (34px) to (32px) on mobile expansion. Portrait and timeline nodes use rounded squares, while circular controls and status dots use a full round shape. The frontmatter records their implemented radius variants. Internal separators stay thin and low contrast. Avoid turning the individual list row into a second sheet inside its parent.

## Components

### Buttons

Pill actions are compact and confident. Primary actions use semantic primary colors; secondary hero actions use the glass material and its thin highlight border. Desktop actions have a minimum height (52px); mobile hero actions become (48px). Hover raises hero actions slightly (2px), active compresses them to (.97), and keyboard focus uses a (3px) ring with a (5px) offset. Circular social, carousel, and header controls have (44px) targets. Disabled buttons show reduced opacity (.65).

### Chips

Technology labels use the tag radius, muted text, and a subtle fill. Category badges over photography use a dark translucent pill with white text. These labels identify content; they do not share the selected-state styling of interactive filters.

### Cards / Containers

The about narrative and skills browser sit in shared frosted sheets. Projects, achievements, and footer use the same visible glass material with component-specific radii. Experience retains open text columns with no reading-card background, border, or shadow. Projects use inset screenshots, a disclosure title with chevron, compact metadata, technology tags, and bottom-aligned actions. Project cards omit standalone personal-role and ownership labels, as requested by the user. All project screenshots and achievement photographs fill their preview frames with cover fitting, preserving proportions and cropping excess edges. The user explicitly wants filled containers without letterboxing. Project image frames clip any per-image zoom inside their rounded edges; focal position and scale keep the subject centered when the source photograph is wider than the subject. Project descriptions clamp to three lines when closed and expose the full original description when expanded. Achievements pair image-led cards with a dark rank pill and separated date metadata. In the desktop three-column grid, a lone final card sits in the middle column. Footer content uses a low-contrast frosted sheet.

### Inputs / Fields

Contact fields sit on a dark sheet with a slightly lighter field fill, subtle pale border, light text, and muted placeholder/icon color. Fields use the control radius and an icon inset. Focus changes the field border to light purple and preserves the global outline. Sending, success, and failure use blue, green, and red tinted submit states with matching dark text, plus explicit status copy; disabled states prevent repeat submission during those states.

### Navigation

The navigation is a near-black translucent Dynamic Island with a purple identity dot, muted links, circular controls, and a white contact pill. Its intrinsic width folds the measured desktop links on downward scroll and reveals them on upward scroll, hover, or keyboard focus. The desktop contact action appears after the hero actions leave view; hidden links and contact controls are inert. The current anchor has a purple underline.

Mobile expands the capsule width and reveals a stacked menu through a grid-row height transition. Escape, outside pointer or focus, and anchor selection close it; Escape and menu selection return focus to the toggle. Hidden mobile content is inert. Theme selection is persisted in local storage and initialized before rendering page content.

### Skills Browser and Segmented Filters

Skills categories have an ink-filled selected state, subtle fill hover, and explicit pressed state. The content panel combines names, original icons, and compact purple proficiency marks. Arrow controls allow category browsing. Project filters use a gray segmented track with a contrasting raised selected thumb and explicit pressed state. On mobile the segments distribute across the available width.

The profile portrait stays upright and still. Ordinary action transitions last around (180–200ms). Island width and menu transitions last (520–680ms) with the same easing. The hero uses the local Masalabs domain-warped WebGL field at half resolution, capped at (30 draws/s); it pauses offscreen and while the document is hidden, and follows runtime reduced-motion changes. A static CSS wallpaper remains available without WebGL or motion. Timeline progress tracks scroll, becoming fully drawn with reduced motion. Reduced motion also removes CSS animations and transitions and makes scrolling immediate.

## Do's and Don'ts

### Do:
- **Do** use semantic light/dark tokens for reading surfaces and text.
- **Do** group related reading rows within a shared frosted sheet and preserve the open experience timeline.
- **Do** retain a visible focus outline and expose selection and disclosure state.
- **Do** keep real portfolio imagery legible within its rounded crop.
- **Do** suppress motion and smooth scrolling when reduced motion is requested.

### Don't:
- **Don't** place the animated hero wallpaper behind long reading content.
- **Don't** give every content row a shadow or its own floating card.
- **Don't** replace the purple detail color with broad saturated reading surfaces.
- **Don't** treat fallback system fonts as the intended display face.


### Publication Assets and Access

The social preview is a 1200 x 630 still of the actual light-mode hero wallpaper with all content overlays hidden for capture. It contains no text. The favicon uses a circular crop of the same wallpaper with transparent corners, provided as SVG and a multi-size ICO fallback. Home-screen icons use a centered square crop of the same still. The manifest identifies Ariel Sulton and uses the light grouped-surface background. Canonical and social URLs retain the existing public domain.

The profile uses a 640 x 640 WebP derived from the original transparent PNG, preserving alpha and the existing portrait crop. Keyboard visitors can reveal a skip-to-content pill before the island; it focuses the main landmark on both the homepage and not-found page. Reduced-motion timeline presentation is handled in CSS so server and initial client markup agree. Starter demo pages and APIs are absent.

### App Landing Pages

The Simak landing page at `/apps/simak` shares the portfolio's centered hero, display typography, purple detail, reflective glass panel, pill actions, and rectangular wallpaper edge. `HeroBackdrop` owns the shared animated wallpaper and static reduced-motion fallback for both routes. The app icon sits above its name panel; app-specific copy and release status remain intact, with actions below the panel. The first themed product screenshot follows the hero on the reading ground. Subsequent sections use the existing section rhythm and shared frosted surface rule. Theme selection persists between the app and portfolio; screenshot variants follow that same selection. The standalone island offers a route back to the portfolio.
